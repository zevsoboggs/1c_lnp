# Love&Pay — Админка

Внутренняя админ-панель в стиле 1С поверх нескольких API: платёжной платформы
Love&Pay, виртуальных карт PAY.SPACE, курса RAPIRA и Telegram мини-аппа.

## Архитектура

Одно приложение из двух частей:

- **Фронт** — React + Refine + Ant Design (Vite). Стилизован под интерфейс 1С.
- **Бэкенд** (`server/`) — Express. Держит все секреты, проксирует запросы к
  внешним API (подставляя ключи на своей стороне), считает HMAC-подпись для
  PAY.SPACE, хранит пользователей/роли/сессии и расчётные листы в Postgres.

Ни один ключ не попадает в браузер: клиент общается только со своим бэкендом
через `/api/*` и `/admin-api/*`, ключи добавляются на сервере.

## Возможности

Платежи (транзакции, инвойсы, возвраты), партнёры и их иерархия, модерация,
финансы и расчёты, выплаты и выводы, наценки, виртуальные карты, KYC,
безопасность (AML-Guard, аудит плательщиков, декларации), журналы, разделы
мини-аппа (заказы, пользователи, рефералка, рассылки, техработы) и
администрирование (пользователи системы, роли с правами по разделам).

Вход по логину/паролю, роли с тремя уровнями доступа на каждый раздел
(нет / чтение / полный), проверка прав на сервере на каждый запрос.

## Разработка

```bash
npm install
cp .env.example .env   # заполнить реальными значениями
npm run dev            # фронт :5273 + бэкенд :5274 одной командой
```

Первый запуск создаёт таблицы и пользователя `admin`; пароль печатается в
консоль один раз (или задаётся через `ADMIN_BOOTSTRAP_PASSWORD`).

## Прод (Render)

`render.yaml` описывает единый веб-сервис. В проде один процесс отдаёт и API,
и собранный фронт (`SERVE_CLIENT=1`). Секреты (`sync: false`) вводятся в
дашборде Render, в репозиторий не попадают.

```bash
npm run build   # tsc + vite build → dist/
npm start       # прод-сервер (читает переменные окружения)
```

## Переменные окружения

См. `.env.example`. Секретные: `DATABASE_URL`, `ADMIN_API_KEY`,
`PAYSPACE_API_KEY`, `PAYSPACE_SECRET`, `MINIAPP_ADMIN_KEY`,
`KYC_BILLING_CONFIRM_CODE`. В прод `ADMIN_INSECURE_COOKIE` не задавать —
cookie сессии должна быть `Secure`.
